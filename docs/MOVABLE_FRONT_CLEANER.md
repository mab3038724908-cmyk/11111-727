# 可移动前清扫装置改造说明

## 1. 当前已有能力

当前代码已经把“底盘路径”和“清扫工具中心”分开：

- 实测刷盘矩形位于车体系前方 `x=+0.14..+0.52m`。
- 刷盘半宽为 `0.34m`。
- `CleanerCommand.offset_m` 表示相对底盘中心线的横向偏移，正值为车体左侧。
- 默认模拟最大横移量为 `0.25m`。
- 每个路径点都有 `mode / offset_m / boundary_type / cleaning_enabled`。
- 对建议偏移会执行完整刷盘矩形的静态地图碰撞检查。
- 规划结果同时提供 `cleaner_center_path`、居中刷洗覆盖率和伸出新增面积。

当前的 `EDGE_*` 语义仍未连接真实执行器。它不能证明装置在指定时刻真的到位。

## 2. 实施前必须由项目方提供的硬件数据

不要在参数缺失时猜测：

1. 运动自由度：左右横移、伸缩、摆臂还是组合运动。
2. 机械零位和正方向。
3. 最小/最大位置及软、硬限位。
4. 最大速度、加速度、减速度和方向反转时间。
5. 命令到动作的典型与最坏时延。
6. 位置反馈类型、频率、分辨率和超时行为。
7. 清扫头完整碰撞多边形随位置的变化。
8. 有效刷洗区域随位置、转速和车速的变化。
9. 门口、急转、倒车和停止时是否必须收回。
10. 卡滞、限位异常、反馈丢失时的安全状态。

建议将这些参数放入独立配置，而不是硬编码在规划器中。

## 3. 推荐架构

```text
底盘名义路径 (x,y,yaw)
        ↓
边界语义分类（墙/障碍/门/分区缝/用户边界）
        ↓
清扫头候选 offset(s)
        ↓
静态几何校验 + 机械行程校验
        ↓
时间参数化（速度/加速度/时延）
        ↓
联合轨迹 (x,y,yaw,offset,mode,enabled,t)
        ↓
离线覆盖率与碰撞复核
```

清扫头调度不应修改标准 ROS Pose；应作为等长 profile 或带时间戳的独立轨迹输出。上车后的执行适配器由机器人所有者实现。

## 4. 推荐状态与规则

- `CENTER`：普通填充，工具居中。
- `LEFT/RIGHT`：仅在真实物理墙边、完整刷盘安全且有覆盖收益时伸出。
- `RETRACT`：区域间连接、门口、狭窄处、急转、倒车或状态不确定时收回。
- `IGNORE/OFF`：不应刷洗的分区缝、开放边界或禁区附近。

至少满足：

```text
offset_min ≤ offset(t) ≤ offset_max
|d(offset)/dt| ≤ actuator_speed_limit
|d²(offset)/dt²| ≤ actuator_acceleration_limit
```

装置未在允许误差内到位时，不能把目标地面记作已清扫。

## 5. 优化目标

建议以硬约束优先的分层目标，而不是单一加权和：

1. 底盘与清扫头碰撞均为 0。
2. 清扫头状态轨迹满足机械动力学和限位。
3. 实际刷洗覆盖率不低于当前居中基线。
4. 尽可能增加物理墙边覆盖。
5. 尽可能减少底盘贴墙、底盘里程、原地转向和清扫头往复次数。
6. 控制清扫头动作频率，避免每几个路径点左右抖动。

## 6. 如果使用机器学习

可学习的内容：区域访问顺序、扫带方向、门口入口/出口选择、清扫头候选偏移或代价估计。

建议输入特征：局部地图、边界类型、距墙距离、路径曲率、车速、距门口距离、当前/目标 offset、区域出口、剩余覆盖掩码。

模型输出只能是候选。候选必须经过确定性的：

- 完整车体碰撞检查
- 完整清扫头碰撞检查
- 未知区检查
- 执行器行程/速度/加速度检查
- 路径连续性检查
- 覆盖率门槛

任何校验失败都回退到确定性基线或收回清扫头，不能直接执行未经证明的策略。

## 7. 推荐输出合同

每个路径点：

```json
{
  "index": 0,
  "base_xy_m": [0.0, 0.0],
  "arrival_yaw_rad": 0.0,
  "departure_yaw_rad": 0.0,
  "hard_stop": false,
  "cleaner_center_xy_m": [0.0, 0.0],
  "cleaner": {
    "mode": "EDGE_CENTER",
    "lateral_offset_m": 0.0,
    "cleaning_enabled": true,
    "boundary_type": "NONE"
  }
}
```

真实执行阶段再增加 `timestamp / target_velocity / feedback_tolerance / timeout`。
段和区域归属由同一 JSON 顶层的 `segments` 与 `regions` 提供，索引通过 `path_start_index/path_end_index` 对齐。可直接运行 `tools/export_plan_contract.py` 生成此合同。
