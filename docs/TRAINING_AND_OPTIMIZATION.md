# 训练与优化边界

## 先明确现状

本包没有预训练模型，也没有假装存在训练数据。当前基线是确定性几何规划器；`maps/9.*` 是一个真实回归样例，`benchmark_synthetic_coverage.py` 能生成可重复的合成场景。开发者可以选择传统搜索、贝叶斯优化、监督学习或强化学习，但交付结果首先要在离线评估器中证明有效。

## 推荐可学习决策

- 房间/区域访问顺序。
- 每区扫带主方向。
- 同一房间的入口、出口和扫带起始端。
- 多条安全连接候选中的排序。
- 可移动清扫头的候选模式、偏移量和动作时机。

不建议让模型直接输出未经校验的连续底盘控制量。本包不含动态障碍、定位误差、底盘动力学或真实清扫头反馈，单靠这里的数据无法证明实车安全。

## 训练样本建议

每个输入样本至少保存：

```text
地图栅格、known-free 掩码、机器人起点、选择区、禁区、车体参数、
清扫头参数、候选区域图、基线计划、随机种子、算法版本
```

每个输出至少保存：

```text
区域顺序、段结构、完整轨迹、清扫头状态轨迹、全部硬约束结果、
覆盖率、路径长度、交叉、重复、转向、清扫头动作次数、规划耗时
```

训练集、验证集和测试集应按地图/建筑布局拆分，不能只把同一张地图的不同起点随机打散，否则会造成地图泄漏。

## 目标函数顺序

先做字典序硬门槛，再比较质量，不能用加权总分掩盖碰撞：

1. 底盘碰撞、工具碰撞、未知区侵入均为 0。
2. 路径连续、区域完成、执行器约束全部通过。
3. 可服务覆盖和实际刷洗覆盖不低于基线门槛。
4. 再减少非必要交叉、重复、里程、转向、工具往复和规划时间。

模型只负责提出候选。候选必须送回确定性校验器；失败则回退到本包基线。这一安全门不得由训练代码关闭。

## 移动清扫装置的特殊要求

现在只知道“前部装置可移动”，尚不能确认它是横移、摆臂、伸缩或多自由度。现有 `offset_m` 只是横向模拟接口，不等于最终机构模型。拿到机械数据后，应把动作空间从一个标量升级为真实关节状态，并同步修改：

- 工具运动学和随状态变化的碰撞多边形；
- 随状态变化的有效刷洗区域；
- 速度、加速度、时延、限位与反馈约束；
- 底盘路径与工具动作的联合时间参数化；
- 门口、倒车、急转、故障时的强制收回规则；
- 覆盖率记账：只有反馈确认到位后的刷洗才算完成。

在这些数据给出前，开发者可以设计可配置接口和测试桩，但不得把默认 `±0.25m` 当作实物最终参数。
